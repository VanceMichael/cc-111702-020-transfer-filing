# 联合产权资料报送工作台
本项目用于收集单持有人材料，选择代表，上传草稿并按门户受理号结束申请。
运行环境为 Node.js 22.23.4，仅使用标准库，没有运行时安装步骤。数据均为本地合成资料，默认来源只监听回环地址，不连接真实业务网站或真实账号。
## 运行
```bash
npm run build
npm test
npm run demo
```
演示会在进程内启动实际本地 HTTP 来源，办理正常业务，打印领域结果及来源请求，然后关闭服务。端口由系统分配，数据保存在内存，不影响已启动的服务。
持续运行时先执行 `npm run source`，再在另一个终端执行 `npm start`。默认来源端口为 4101，业务端口为 4100；可通过 `SOURCE_URL`、`PORT` 和 `STATE_PATH` 指定回环来源、端口及状态文件。终止进程使用 Ctrl+C。删除 `var/` 可清空本地持久状态。
## 业务接口
`POST /collect` 接收本次办理参数，空对象使用本地样例的正常条件；`GET /state` 查询当前业务结果；`GET /health` 查询服务状态。一次办理失败不会提交中间业务状态，接口以 422 返回拒绝原因。状态文件按完整写入后替换，单进程内串行办理。
- `confirmations`：接纳持有人对申请内容的确认。
- `representation`：确定代表可办理的门户草稿。
- `submissions`：组装材料并关联门户受理或补正。
来源接口的字段约定见 `docs/source-contract.md`。`fixtures/source.json` 是可独立启动的来源响应数据，来源 `GET /trace` 返回实际请求；脚本每条路由依次返回响应，超出后重复最后一条，可表达延迟、断连和明确拒绝。请求轨迹只记录是否带授权，不回显授权原文。
## 测试
测试覆盖领域正常结果、状态重开、HTTP 办理与查询、来源拒绝后的回滚、并行存储更新、本地访问边界和来源请求追踪。每个测试使用临时端口与独立状态，不依赖执行顺序。构建仅检查源码语法，不获取依赖。
